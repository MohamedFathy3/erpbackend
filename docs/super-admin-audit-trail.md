# سجل التدقيق للـSuper Admin

## ما الذي يسجله

- كل طلب API صادر عن مستخدم موثق: المسار، الطريقة، وقت التنفيذ، المدة، النتيجة ورمز HTTP.
- بيانات الطلب المنقحة، وملخص الخطأ الذي أعاده الخادم عند الفشل.
- اسم/معرّف المستخدم ونوع حسابه، الفرع، واسم/معرّف الـTenant.
- محاولات تسجيل الدخول الناجحة والفاشلة ومحاولات الوصول المرفوضة (401/403).
- مشاهدات صفحات التطبيق ومحاولات فتح نافذة الطباعة. أحداث الطباعة تثبت فتح/إغلاق نافذة الطباعة، ولا تستطيع المتصفحات إثبات خروج ورقة فعلية من الطابعة.
- تدعم لوحة الـSuper Admin التصفية حسب العميل والنتيجة ونوع الحدث والطريقة والتاريخ والبحث في المستخدم والمسار والخطأ.

يُحجب تلقائيًا ما يتشابه اسمه مع كلمة مرور أو token أو سر أو بيانات بطاقة أو PIN. بيانات تسجيل الدخول تحفظ كمُعرّف مقنّع فقط. لا يخزن السجل استجابة API كاملة؛ بل ملخص الخطأ فقط. السجل الجديد يسجل النشاط ابتداءً من نشره، ولا ينشئ تاريخًا بأثر رجعي. توجد أيضًا سجلات Spatie القديمة لبعض تغييرات الموديلات.

## تطبيق التغيير

1. انشر فرع `feature/super-admin-audit-trail` من backend وfrontend إلى بيئة الاختبار/الإنتاج وفق آلية النشر المعتادة.
2. نفّذ ترحيلات Laravel في بيئة التطبيق بعد أخذ نسخة احتياطية والتأكد من اتصال قاعدة البيانات:

   ```bash
   php artisan migrate --force
   ```

3. افتح مركز الإدارة العليا ثم تبويب **سجل التدقيق**، واختر الـTenant المطلوب.
4. اختبر على بيانات غير إنتاجية: تسجيل الدخول الناجح/الفاشل، فتح صفحات، تغيير غير مالي، محاولة محظورة، وفتح الطباعة.

## إعادة المحاولة

- طلبات GET/HEAD الفاشلة يمكن إعادة تشغيلها مباشرة.
- طلبات POST/PUT/PATCH الفاشلة القابلة لإعادة الإرسال تحتاج إلى تأكيد صريح في الواجهة، وتستخدم البيانات المنقحة المسجلة. تُضاف هوية الـTenant إلى جسم طلب الإنشاء عند الحاجة، ويحتفظ الحدث الجديد بمعرّف الحدث الأصلي.
- لا يعاد تشغيل الحذف أو تسجيل الدخول أو الطباعة أو التنقل بين الصفحات، ولا الطلبات التي تحتوي بيانات سرية محجوبة أو ملفات مرفوعة.
- **خطر التكرار:** قد تكون الفاتورة أو الدفعة أو القيد قد حُفظت بالفعل رغم أن الرد وصل كخطأ أو انقطع الاتصال. لذلك يجب فحص السجل والـTenant والمستند أولًا قبل تأكيد إعادة الإرسال؛ وقد تنشأ معاملة مكررة. لا يوجد ضمان idempotency عام للـendpoints الحالية.

## حدود التغطية

السجل يلتقط طلبات الخادم والتنقل بين الصفحات ومحاولات الطباعة. الأحداث التي تحدث محليًا في المتصفح دون طلب API (مثل تحريك مؤشر أو تعديل حقل لم يُرسل بعد) لا تعتبر عملية محفوظة ولا تسجل. عند بعض الاستثناءات العامة يكون السبب المتاح للواجهة هو رسالة الخطأ ورمز HTTP؛ ولا نخزن stack trace أو أسرار تشغيلية.
